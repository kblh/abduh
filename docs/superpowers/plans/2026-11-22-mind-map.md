# Mapa souvislostí (mind map) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pohled „Mapa“ (SVG plátno s tažením a zoomem) dostupný z detailu kapely, stylu, nástroje a tagu, který ukáže tři úrovně souvisejících kapel s popisky vztahů a klikacími kolečky.

**Architecture:** Čistý model grafu (`buildMap`) a čistý radiální layout (`layoutRadial`) se testují v `node --test`; vlastní pan/zoom nad Pointer Events (čistá matematika `viewport.js` + tenký řadič `pan-zoom.js`) hýbe jednou `<g>` v `<svg>`; view `views/map.js` vše spojí. Route `#/<sekce>/<id>/map`.

**Tech Stack:** vanilla ES moduly, SVG, CSS tokeny z `tokens.css`, `node --test`. Žádná nová závislost.

**Spec:** `docs/superpowers/specs/2026-11-22-mind-map-design.md`

## Global Constraints

- Vanilla ES moduly, bez build kroku frontendu, bez nových runtime závislostí, žádný další request kromě existujícího `data.json`.
- Mapa vzniká jen z dat `store` (`bandsByStyle`, `bandsByInstrument`, `bandsByTag`, `bandsByCountry`, `byId`, `sortedBands`); nic se nevymýšlí.
- Limity (výchozí): celkem ≤ 80 uzlů; úroveň 1 ≤ 12; úroveň 2 ≤ 3 na uzel; úroveň 3 ≤ 2 na uzel; země max 3 místa na úrovni 1 (u kapely jen se zemí 8).
- Deterministický výběr: víc sdílených vztahů, pak má fotku, pak abecedně (`normalize` z `text.js`).
- Kapela se na mapě objeví nejvýše jednou; střed se neopakuje.
- Zoom meze 0,25–3; práh tažení 5 px; `touch-action: none` na plátně; `prefers-reduced-motion` = bez setrvačnosti.
- UI česky; názvy entit tak, jak jsou v datech; styly přes `prettyStyle`.
- Motivy: jen CSS proměnné z `tokens.css`; světlý i tmavý.
- Commity jen na výslovnou žádost uživatele (paměť projektu); kroky „Checkpoint“ znamenají spustit testy, ne commitovat.

## Review Focus

- Kapela jen se zemí, bez stylu/nástroje/tagu (většina sbírky): mapa se zemí na hranách, ne prázdná (Task 2).
- Kapela bez jakéhokoli souseda (jediná v zemi bez vztahů): prázdný stav s větou a odkazem zpět (Task 2, Task 5).
- Obří hub (styl s 117 kapelami, země se 319): limit uzlů dodržen a vznikne uzel „+N dalších“ s odkazem na filtrovaný seznam (Task 2).
- Odkaz na člena, který v datech neexistuje (`members: [{id:'x'}]` s chybějícím `x`): bez pádu, hrana se vynechá (Task 2).
- ID s diakritikou/speciálními znaky v hashi (`#/bands/b%C3%A9la/map`): správně se rozparsuje a odkazy na uzly jsou správně zakódované (Task 1, Task 2).
- Tažení nesmí vyvolat klik na odkaz pod prstem; krátký klik/tap ano (Task 4).
- Neexistující `id` v `/map` nebo neznámý druh: 404 jako u detailu (Task 5).

### Task 2: Model grafu `buildMap`

**Files:**
- Create: `public/app/map/graph.js`
- Test: `tests/web-map-graph.test.js`

**Interfaces:**
- Consumes: `buildStore` z `store.js` (indexy viz Global Constraints), `normalize`, `prettyStyle` z `text.js`, `buildHash` z `router.js`.
- Produces:
  - `export const DEFAULT_LIMITS = { total: 80, l1: 12, l2: 3, l3: 2, countryL1: 3, countryOnlyL1: 8 }`
  - `export function buildMap(store, { kind, id }, limits = DEFAULT_LIMITS) → { nodes: Node[], edges: Edge[] }` (nic nehází; neznámé `id` → `{nodes:[], edges:[]}`)
  - `Node = { key, kind: 'band'|'style'|'instrument'|'tag'|'more', id?, label, level: 0..3, parent: string|null, image?: string, flag?: string, href }`; `key` = `<kind>:<id>` (u „more“ `more:<parentKey>:<rel>:<relId>`); `href` např. `#/bands/<enc id>`, `#/styles/…`; „more“ → `#/bands?<style|instrument|tag|country>=<enc relId>`; label „+N dalších“.
  - `Edge = { from, to, rel: 'member'|'style'|'instrument'|'tag'|'country', relId: string|null, label, href: string|null }`; label např. „styl · rai“, „nástroj · oud“, „tag · woman“, „země · Mali“, „člen“; `href` na detail entity vztahu (člen: `null`).
- Pravidla: viz spec „Model grafu“. Člen: `members` položka `{id,name}` ukazující na existující kapelu, oběma směry; text-only člen se ignoruje. Síla vztahů: člen > styl > nástroj > tag > země; kapela sdílející víc vztahů má jednu hranu s nejsilnějším. Střed style/instrument/tag: hrany na úrovni 1 mají `rel` = druh středu, label „styl“/„nástroj“/„tag“, `relId` = id středu; úrovně 2–3 nepoužívají vztah ke středu. Země na úrovních 2–3 jen když uzel nemá silnější vztah, který by dal kandidáty. Kvóty a řazení podle Global Constraints.

- [ ] **Step 1: Failing tests** (malý inline `data` + `buildStore`; jeden hub s 40 kapelami stejného stylu a 330 kapel s `countries:['france']`; asserts):
  - `kapela jen se zemí` → ≥1 uzel úrovně 1 a všechny hrany mají `rel:'country'`, label `země · <name>`.
  - `bez souseda` → `nodes.length === 1` (jen střed), `edges.length === 0`.
  - `hub`: `nodes.length <= 80`, existuje uzel kind `more` s label `+N dalších` a `href` `#/bands?style=<id>`.
  - `deterministický`: dvě volání dají `deepEqual` výsledek.
  - `kapela maximálně jednou`: klíče uzlů unikátní, střed jen jednou.
  - `střed style`: uzly úrovně 1 jsou kapely se stylem, hrany `rel:'style'`, label `styl`.
  - `střed instrument` a `střed tag` analogicky.
  - `člen`: A má `members:[{id:'b',name:'B'}]` → mapa A obsahuje B s `rel:'member'`; mapa B obsahuje A (zpětně).
  - `dangling člen`: `members:[{id:'neexistuje',name:'X'}]` nehází a nevytvoří uzel.
  - `diakritika`: kapela `id:'béla'` → `href` `#/bands/b%C3%A9la`.
  - `silné před zemí`: kapela se stylem i zemí; kandidát sdílející styl a zemi má jednu hranu `rel:'style'`; země nezabere víc než `countryL1` míst na úrovni 1.

### Task 4: Pan/zoom (matematika + řadič)

**Files:**
- Create: `public/app/map/viewport.js`, `public/app/map/pan-zoom.js`
- Test: `tests/web-map-viewport.test.js`

**Interfaces:**
- Produces (`viewport.js`, čisté funkce, transformace `T = {x, y, k}`: `screen = world*k + (x,y)`):
  - `export const K_MIN = 0.25, K_MAX = 3`
  - `export function zoomAt(t: T, factor: number, px: number, py: number): T` (bod pod kurzorem zůstane na místě, `k` omezeno na [K_MIN, K_MAX])
  - `export function fitTransform(bounds, size: {w:number,h:number}, pad = 40): T` (celé `bounds` se vejde a je vycentrované; `k` omezeno na [K_MIN, 1])
  - `export function panBy(t: T, dx: number, dy: number): T`
  - `export function inertiaStep(v: {x:number,y:number}, dtMs: number): { v: {x,y}, dx: number, dy: number }` (exponenciální útlum, `v` v px/ms; pod prahem 0,01 → nula)
- Produces (`pan-zoom.js`): `export function attachPanZoom(el: SVGSVGElement, { world: SVGGElement, onChange?: (t: T) => void, reducedMotion?: boolean }) → { get: () => T, set: (t: T) => void, fit: (bounds) => void, zoomBy: (factor: number) => void, wasDrag: () => boolean }`. Nastaví `transform` na `world` přes `requestAnimationFrame`; Pointer Events (pointer capture): 1 ukazatel = tažení se setrvačností (vypnout při `reducedMotion`), 2 ukazatele = pinch (zoom kolem středu), `wheel` (`preventDefault`, faktor `exp(-deltaY*0.0015)`, Ctrl/pinch na trackpadu stejně), klávesy na `el` (`tabindex=0` na wrapperu řeší view): šipky pan 60 px, `+`/`-` zoom 1,2×, `0` = fit. Tažení nad 5 px nastaví `wasDrag()` true a pohltí následný `click` ve fázi capture (`el.addEventListener('click', e => { if (dragged) { e.preventDefault(); e.stopPropagation(); } }, true)`); krátký klik/tap projde.

- [ ] **Step 1: Failing tests** pro `viewport.js`: `zoomAt` drží bod pod kurzorem (spočítej svět před/po), respektuje K_MIN/K_MAX; `fitTransform` — bounds 2000×1000 do 1000×500 dá `k ≈ 0,45` a střed bounds ve středu okna; malé bounds → `k ≤ 1`; `panBy`; `inertiaStep` konverguje k nule a součet `dx` je konečný.
- [ ] **Step 2:** FAIL.
- [ ] **Step 3: Implement** `viewport.js`, pak `pan-zoom.js` (bez testu v node, ověří se v Task 7; test na `wasDrag` logiku přes čistou pomocnou `exceedsDragThreshold(dx, dy, threshold = 5)` exportovanou z `viewport.js` a otestovanou).
- [ ] **Step 4:** PASS.
- [ ] **Step 5: Checkpoint:** `npm test`.
