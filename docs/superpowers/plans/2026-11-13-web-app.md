# Abduh web app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read-only SPA over `public/data.json` with fast, diacritics-insensitive search and all screens from the PDF designs, mobile and desktop, light and dark.

**Architecture:** Static `public/index.html` + ES modules, hash router, data loaded once and indexed in memory. Logic that needs no DOM (text normalization, router parsing, store indexes, search) lives in pure modules tested with `node --test`; views are plain DOM functions `view(ctx) -> HTMLElement`. `scripts/build.js` gains an `added` date per entity.

**Tech Stack:** Vanilla JS (ES modules), CSS custom properties, node `--test`. No framework, no bundler, no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-13-web-app-design.md` (designs: `~/Desktop/Abduh – visual identity & screens.pdf`, 15 pages; the PDF is authoritative for visuals and tab set).

## Global Constraints

- Vanilla JS/CSS/HTML; no build step for the frontend; static files from `public/`.
- UI text Czech; entity names shown as in the data (English); style slugs shown with spaces instead of hyphens (`a-capella` → `a capella`).
- No translation of data. Only exception: search words `woman`/`žena` map to tag `woman`; the tag shows as the black label `ŽENA` in lists.
- Never invent content: elements without data (instrument category, style description, related styles, country subregion, catalogue number, handwritten notes) are not rendered. Bio/description comes from `body` when non-empty.
- Hash routes: `#/`, `#/bands`, `#/bands/:id`, `#/cds`, `#/cds/:id`, `#/styles`, `#/styles/:id`, `#/instruments`, `#/instruments/:id`, `#/countries`, `#/countries/:id`, `#/shelves`, `#/shelves/:id`, `#/search?q=…`. Filters in query: `country`, `style`, `instrument`, `photo=1`, `sort=new`. Unknown route or id → 404 view.
- Mobile-first 375 px + desktop 1280 px; desktop top nav (Domů, Kapely, CD, Styly, Nástroje, Země, Poličky), mobile bottom tab bar with exactly six tabs (Domů, Kapely, CD, Styly, Nástroje, Země); search field in every header; `/` focuses it.
- Themes via `data-theme` (`light` | `dark`), default `prefers-color-scheme`, manual toggle persisted in `localStorage` (wrapped in try/catch); respect `prefers-reduced-motion`.
- Fonts self-hosted (woff2 in `public/fonts/`), three roles: typewriter, handwriting, serif; must support Czech diacritics.
- `added`: ISO date of an entity file's first git commit, ignoring commits that add more than 50 data files; missing when no git history; UI hides "new" features for entities without it. "New" = within 30 days.
- Schema authority: `scripts/lib/validate.js`, `scripts/lib/entity-file.js`. Bands: `name, countries, styles, instruments, members, tags, image, links, body`; CD: `name, bands, year, label, styles, image, links, body`; shelf: `name, bands, cds, body`; country: `name, continent, flag, body`; instrument: `name, icon, body`; style: `name, body`. `image` is already `img/…` in `data.json`.
- Existing tests keep passing (`npm test`); commit after each task, never commit `design.md`.

## Review Focus

- Empty or whitespace-only query returns no groups and does not throw; queries with regex characters (`(`, `*`, `\`) match literally → Task 3.
- Diacritics both directions (`rai` finds `raï`, `Čech` finds `Cech`) and percent-encoded hash (`#/search?q=ra%C3%AF`) decode correctly → Tasks 2, 3.
- Dangling or missing references (CD whose band is absent, band without styles/instruments, shelf with no items, `body` undefined) never crash views → Tasks 3, 6.
- 2 700-row list stays smooth and resets scroll when a filter changes; only a window of rows exists in the DOM → Task 6.
- `localStorage` throwing (private mode) does not break theme or app start → Task 4.
- Long names (e.g. `africa-express-presents-maison-des-jeunes`) never overflow rows at 375 px → Task 5.

### Task 3: store and search (pure)

**Files:** Create `public/app/store.js`, `public/app/search.js`; Test `tests/web-store.test.js`, `tests/web-search.test.js`.

**Interfaces:**
- Produces `loadData(url: string): Promise<Data>` (fetch JSON, throws on non-2xx). `buildStore(data: Data): Store`:
  - `store.data` (raw), `store.byId.{bands,cds,styles,instruments,countries,shelves}: Map<string,Entity>`;
  - `store.bandsByCountry|bandsByStyle|bandsByInstrument: Map<string, Band[]>` (sorted by `normalize(name)`);
  - `store.cdsByBand: Map<string, Cd[]>`; `store.shelvesOf(type: 'band'|'cd', id: string): Shelf[]`;
  - `store.continentOf(countryId): string`; `store.sortedBands: Band[]` (by normalized name).
  - Missing/undefined arrays on entities are treated as empty; references to unknown ids are skipped silently.
- Produces `isNew(entity, today: Date, days = 30): boolean` (false without `added`); `recentlyAdded(store, n: number): Entity[]` (bands and CDs with `added`, `added` desc then name asc, no entries without `added`).
- Produces `buildIndex(store): Index`; `search(index: Index, query: string): { total: number, groups: Record<'bands'|'cds'|'styles'|'instruments'|'countries'|'shelves', Hit[]> }`; `Hit = { id: string, reason: 'name'|'country'|'style'|'instrument'|'tag' }`.

Search rules (spec): normalize query and fields; split query on spaces, **all words must match** (AND); entity names for all six types; a band additionally matches through the normalized names of its countries, styles, instruments and tags (`woman` and `žena` both map to tag `woman`), `reason` ≠ `name` in that case; rank = starts with query < word-start < contains < via relation, ties alphabetical; empty/whitespace query → `{ total: 0, groups: all empty }`; no regex is built from user input.

- [ ] **Step 1: Failing tests** with a small inline dataset (3 bands in Mali/Algeria, styles `desert-blues`, instrument `kora`, tag `woman`, one CD, one shelf): `search(idx,'kora')` finds the instrument and the bands with `reason:'instrument'`; `search(idx,'  ')`→total 0; `'(*'` and `'\\'` don't throw and return 0; `'rai'` finds a band named `Raï`; AND semantics: `'ali toure'` finds `Ali Farka Touré`, `'ali zzz'` finds nothing; `'žena'` and `'woman'` return the same tagged band with `reason:'tag'`; name-prefix hit ranks before relation hit; `buildStore` tests: `bandsByCountry.get('mali')` order, `cdsByBand`, `shelvesOf('band','tinariwen')`, CD with unknown band id does not throw; `isNew` true within 30 days, false at 31, false without `added`; `recentlyAdded` excludes entities without `added` and orders by date desc.
- [ ] **Step 2: Run** `node --test tests/web-store.test.js tests/web-search.test.js` → FAIL.
- [ ] **Step 3: Implement** both modules; index built once as arrays of `{id,type,name,norm,viaNorms[]}` (linear scan over ~3 000 entries is fast enough, no extra structure).
- [ ] **Step 4: Run** → PASS; also run `node -e` timing check: `search` on the real `public/data.json` for `kora` completes in < 20 ms. **Step 5: Commit** `feat(web): store indexes and search`.
